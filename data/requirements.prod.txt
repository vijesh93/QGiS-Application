# Production data-loader requirements.
#
# The server only ever runs the registration step against COGs that were
# already optimized locally (`--skip-download --skip-optimize --only-register
# --fast-register`), which trusts the `.meta.json` sidecars written by the
# local run and does zero gdalinfo/rasterio-scan work of its own. The actual
# Python-level imports it still hits are register_layers.py's own
# `import rasterio` (unconditional, even in --fast mode) and psycopg2 for the
# DB insert — nothing else in data/requirements.txt (opencv, geopandas,
# rioxarray, pandas, scipy, matplotlib, jupyter/ipykernel/notebook/ipython)
# is ever imported on this path. Keep data/requirements.txt (the full set)
# for local/dev use, where the whole download/optimize/validate pipeline
# actually runs.
#
# numpy is pinned explicitly (matching data/requirements.txt) because
# rasterio==1.3.9's compiled extension was built against NumPy 1.x's ABI —
# leaving numpy unpinned lets pip install the latest NumPy 2.x, which then
# fails with "numpy.core.multiarray failed to import" the moment rasterio
# is imported.
numpy==1.26.4
rasterio==1.3.9
psycopg2-binary
